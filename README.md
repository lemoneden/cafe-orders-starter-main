# Касса кофейни

Это задание не обязательно для выполнения. Если вы хотите закрепить 2 прошедшие темы и заработать дополнительный бонус(ооочень хороший бонус) к сдаче своих работ в этом семестре, то это стоит вашего внимания)

Вы получаете почти готовое приложение — кассу кофейни «Зерно». Бариста выбирает позиции из меню, применяет скидку, оформляет заказ и меняет его статус: «Готовится», «Готов», «Выдан». Гость копит баллы на карте лояльности.

Часть классов не написана. Другая часть работает, но написана так, как писать не нужно: код повторяется, данные открыты для изменения, в интерфейсе есть ошибка. Вам нужно дописать недостающее и переписать неудачный код.

## Запуск

Нужен Node.js версии 20 или новее.

```bash
npm install
npm run dev     # приложение в браузере
npm test        # автоматические тесты
```

Тесты — ваш главный помощник. Для каждой задачи есть свой файл в папке `tests`. Когда задача выполнена, все её тесты становятся зелёными. Можно запускать тесты одной задачи:

```bash
node --test tests/1-menu.test.js
```

Пока задачи 1–3 не выполнены, вместо кассы в браузере будет сообщение об ошибке. Это нормально.

## Структура

```
src/
  core/        EventEmitter, миксин Logger, настройки CafeConfig
  menu/        позиции меню и фабрика
  order/       заказ, сервис заказов, статусы
  discounts/   скидки
  receipt/     печать чека
  loyalty/     карта лояльности
  services/    счётчик продаж
  ui/          интерфейс кассы
  data/        данные меню
tests/         тесты по задачам
```

## Что уже готово и что менять нельзя

- `core/EventEmitter.js` — класс для событий из лекции.
- `core/Logger.js` — миксин для логирования.
- `order/statuses.js` — статусы заказа и разрешённые переходы между ними.
- `data/menu.js` — меню в виде обычных объектов.
- `order/Order.js` — заказ. Его можно менять только в задаче 5.

Файлы тестов менять нельзя.

## Часть 1. Допишите код

Требования к каждому классу подробно расписаны в комментарии в начале файла.

### Задача 1. Позиции меню

Файлы: `menu/MenuItem.js`, `menu/Drink.js`, `menu/Dessert.js`.

- `MenuItem` — абстрактный класс. Создать его через `new` напрямую нельзя.
- Данные хранятся в приватных полях, доступ к ним — через геттеры и сеттеры с проверкой значений.
- `Drink` — напиток. Цена зависит от размера: S дешевле, L дороже.
- `Dessert` — десерт. Признак «веганский» нельзя изменить после создания.
- Каждый класс по-своему отвечает на `getCategory()` и `describe()`.

### Задача 2. Фабрика меню

Файл: `menu/MenuFactory.js`.

Меню приходит в виде обычных объектов (`data/menu.js`). Фабрика превращает их в экземпляры `Drink` и `Dessert`. Интерфейсу не нужно знать, какой класс за какой тип отвечает.

### Задача 3. Сервис заказов и подписчики

Файлы: `order/OrderService.js`, `services/salesCounter.js`.

- `OrderService` хранит оформленные заказы и их статусы, проверяет переходы между статусами и сообщает о событиях через `emit`.
- Миксин `Logger` уже подключён — используйте `this.log(...)`.
- `createSalesCounter` — подписчик. Считает, сколько продано каждой позиции, и учитывает отменённые заказы.

После этой задачи касса откроется в браузере.

## Часть 2. Исправьте и перепишите

В этой части код уже работает. Задача — сделать его правильным, не сломав поведение. Интерфейс кассы после ваших правок должен работать как раньше.

### Задача 4. Настройки кофейни

Файл: `core/CafeConfig.js`.

Что не так:

- Поменяйте в шапке «Лимит позиций в заказе» на 2 и добавьте в заказ три позиции. Лимит не сработает. Разберитесь, почему.
- Настройки лежат в открытом поле `settings`, их можно изменить в обход `set`.
- Через `set` можно записать параметр, которого не существует.

Что сделать: настройки должны существовать в одном экземпляре на всё приложение. Добавьте метод `getAll()`, который возвращает копию всех настроек.

### Задача 5. Скидки

Файлы: `order/Order.js` (геттер `discount`), `discounts/index.js`.

Что не так: все скидки считаются в одном геттере цепочкой `if / else if`. Чтобы добавить новую скидку, придётся править класс `Order`, хотя он не должен ничего знать о конкретных акциях.

Что сделать:

- Вынесите каждую скидку в отдельный класс с методом `calculate(order)`, который возвращает сумму скидки: `NoDiscount`, `LoyaltyDiscount`, `HappyHourDiscount`, `BigOrderDiscount`. Экспортируйте их из `discounts/index.js`.
- В `Order` вместо поля `discountType` добавьте метод `setDiscount(strategy)`. Геттер `discount` должен просто вызывать `calculate` у текущей скидки.
- Правило «скидка не больше суммы заказа» должно сохраниться.
- `DISCOUNT_OPTIONS` и `applyDiscount(order, value)` оставьте с теми же названиями — их использует интерфейс. Для неизвестного значения `applyDiscount` должна выбрасывать ошибку.

### Задача 6. Чек

Файл: `receipt/ReceiptPrinter.js`.

Что не так: принтер проверяет через `instanceof`, какая перед ним позиция, и сам решает, как её назвать. Если в меню появится чай, принтер придётся переписывать.

Что сделать: добавьте в классы меню геттер `displayName` — название для чека: «Латте (M)», «Брауни (веган)», «Чизкейк». Принтер должен использовать только его. Формат чека не меняется.

Подумайте, можно ли после этого упростить `describe()` в классах меню.

### Задача 7. Карта лояльности

Файл: `loyalty/LoyaltyCard.js`.

Что не так:

- Баллы и история лежат в открытых полях. Гость может «накрутить» себе баллы: `card.points = 99999`.
- `spendPoints(-100)` не списывает, а начисляет баллы.
- Все методы создаются внутри конструктора.

Что сделать:

- Баллы и история — приватные поля. Баллы доступны только для чтения через геттер `points`.
- Добавьте метод `getHistory()`, который возвращает копию истории.
- `spendPoints` принимает только целое положительное число.
- Методы `addPoints`, `spendPoints` и `getLevel` оставьте с теми же названиями, но перенесите их в класс.

### Задача 8. Кнопка «Добавить»

Файл: `ui/CafeApp.js`.

После задачи 3 касса откроется, но кнопки «Добавить» в меню не работают, а в консоли браузера появляется ошибка. Найдите причину и исправьте. Для этой задачи тестов нет — проверьте её в браузере.

## Критерии приёмки

| Задача | Что проверяем |
|---|---|
| 1. Меню | Абстрактный класс, приватные поля, геттеры и сеттеры с проверкой, переопределение методов |
| 2. Фабрика | Одна точка создания позиций, понятная ошибка для неизвестного типа |
| 3. Заказы | Наследование от EventEmitter, события с нужными данными, проверка переходов, подписчик с отпиской |
| 4. Настройки | Один экземпляр, закрытые данные, проверка ключей |
| 5. Скидки | Стратегии вместо цепочки условий, `Order` не знает о конкретных скидках |
| 6. Чек | Полиморфизм вместо `instanceof` |
| 7. Карта | Инкапсуляция, методы в прототипе, проверка входных данных |
| 8. Интерфейс | Исправлена потеря `this`, причина объяснена в отчёте |
